# 认识管理后台

管理后台用于编辑博客仓库中的文章、动态和配置。它不会成为博客运行时依赖，也不会替代 GitHub 保存已发布内容。

## 首次连接仓库

第一次登录后，后台会要求连接 GitHub 仓库：

1. 填写仓库所有者。
2. 填写仓库名称。
3. 填写发布分支，通常是 `main`。
4. 点击“验证并连接”。

连接成功后，仪表盘会显示已发布文章、已发布动态、待提交草稿和最近提交。

## 侧栏入口

| 区域 | 入口 | 用途 |
| --- | --- | --- |
| 概览 | 仪表盘 | 查看内容数量、当前仓库、最近提交和后台操作 |
| 概览 | 发布文章 | 使用 Vditor 编写 Markdown，设置文章信息并发布 |
| 概览 | 管理内容 | 在文章与动态之间切换，查看、编辑或删除已发布内容 |
| 概览 | 发布动态 | 编写短内容并设置发布时间 |
| 配置 | 五个配置入口 | 编辑博客外观、组件、功能和页面数据 |
| 记录 | 待提交 | 查看保存在 D1 中但尚未提交的草稿 |
| 记录 | 提交记录 | 查看 GitHub 提交和后台操作记录 |

## 草稿与发布

“保存草稿”和“提交到 GitHub”是两种不同操作：

- **保存草稿**：内容进入 D1，只在后台可见，不会改变线上博客。
- **提交到 GitHub**：后台创建 commit，已发布内容以 GitHub 当前版本为准。
- **批量提交**：在“待提交”中勾选多个草稿，一次合并为一个 commit。

::: warning 不要把 D1 当作内容数据库
D1 只保存后台设置、草稿、登录限流和审计记录。文章、动态和博客配置的已发布版本始终来自 GitHub。
:::

## 提交后的部署

后台提交成功后，只能确认 GitHub 已收到变更。博客是否完成上线，由 Vercel、Netlify 或其他静态托管平台决定。

正常流程是：

```text
后台编辑 → GitHub commit → 托管平台自动构建 → 线上博客更新
```

## 冲突处理

草稿会记录创建时对应的 GitHub 文件版本。若提交前发现文件已经被其他提交修改，后台会提示冲突并默认停止覆盖。

只有确认草稿内容应该取代 GitHub 最新内容时，才选择“强制覆盖”。批量提交中只要有一个未确认冲突，整批内容都不会提交。

## 已发布内容的限制

- Markdown 文章可以在后台查看、编辑和删除。
- MDX 文章可以在列表中看到，但包含组件代码时应在 GitHub 中编辑。
- 删除已发布文章或动态会直接创建删除 commit，不会先进入草稿区。
- 当前不提供图片上传；封面和正文图片使用现有相对地址或网络 URL。
