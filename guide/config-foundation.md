# 基础配置

**入口：后台 → 基础配置**

进入后，通过顶部子菜单切换“站点配置”“个人资料”“公告”和“背景壁纸”。这些设置决定站点身份和首页第一印象。

## 站点配置

**入口：后台 → 基础配置 → 站点配置**  
**手动配置对象：`siteConfig`**

### 站点身份

| 字段 | 含义 |
| --- | --- |
| 标题 | 浏览器标题、页面标题和站点品牌名称 |
| 副标题 | 对站点名称的简短补充 |
| 正式地址 | 站点线上 URL，用于 RSS、Sitemap 和分享信息 |
| 描述 | 搜索摘要和站点介绍 |
| 关键词 | 用于描述站点主题的关键词列表 |
| 开始日期 | 用于计算站点运行天数 |
| 时区 | IANA 时区，例如 `Asia/Shanghai` 或 `UTC` |

语言字段在后台中只读。手动配置时修改 `SITE_LANG`，常用值包括 `zh_CN`、`zh_TW`、`en`、`ja`、`ru` 和 `ko`。

### 主题与页面尺寸

- **主题色色相**：范围为 `0` 到 `360`。它是色相角，不是十六进制颜色。
- **默认模式**：`light`、`dark` 或 `system`。
- **页面宽度**：单位为 `rem`。单侧栏布局通常适合更窄的页面。
- **卡片边框与阴影**：增强内容块层次，但卡片较多时也会增加视觉密度。
- **卡片跟随主题色**：让卡片细节随主题色色相变化。

### Favicon

每个图标项目可以设置：

| 字段 | 说明 |
| --- | --- |
| `src` | 图标地址 |
| `theme` | 可选，限制为亮色或暗色模式 |
| `sizes` | 可选，例如 `32x32`、`192x192` |

若启用 OpenGraph 图片生成，建议至少保留一个 PNG 图标。

### 导航栏品牌

这里配置 Logo 与站点标题；菜单链接在“基础组件 → 导航栏”中管理。

Logo 支持：

- `icon`：Iconify 图标名。
- `image`：本地图片，可额外设置暗色版本。
- `url`：网络图片，可额外设置暗色版本。

还可以控制导航栏是否全宽、菜单左对齐或居中、品牌是否跟随主题色、导航栏是否固定在顶部。

### 页面开关

页面开关控制友链、打赏、留言板、番组计划、相册、追番和动态是否可以访问。关闭后，对应页面返回 404，并自动隐藏使用页面预设的导航入口。

::: warning 页面开关与页面内容不同
例如关闭“相册”会直接停用相册页面；“页面 → 相册”只负责相册数据和展示方式。
:::

### 文章列表

| 设置 | 说明 |
| --- | --- |
| 默认布局 | `list` 单列列表，或 `grid` 多列网格 |
| 移动端默认布局 | 可以单独覆盖移动端布局 |
| 摘要行数 | `0` 表示不截断 |
| 统计图标 | 控制日期、字数、阅读时间旁的图标 |
| 标签位置 | `meta` 显示在标题下，`bottom` 显示在卡片底部 |
| 元数据 | 分别控制发布日期、分类、标签、字数和阅读时间 |
| 网格最小列宽 | 浏览器据此自动计算列数 |
| 瀑布流 | 混合有封面和无封面文章时更适合开启 |

分类导航栏控制首页和归档页顶部的分类快捷入口；归档折叠控制是否默认收起较早年份。

### 文章内容页

- **提醒框主题**：`github`、`obsidian`、`vitepress`、`docusaurus`。
- **Python-Markdown 提醒框**：只建议与 `obsidian` 主题一起使用。
- **上次编辑时间**：控制文章底部的过期提醒卡片。
- **过期阈值**：以天为单位，超过后才显示提醒。
- **分享海报**：允许读者生成分享海报。
- **OpenGraph 图片**：构建耗时明显增加，本地调试时建议关闭。

### 番组、追番与分页

站点配置还包含以下高级数据源：

- **Bangumi 用户 ID**与数据模式：`static` 在构建时获取，`dynamic` 在浏览器中实时获取。
- **Bangumi API 与详情地址**。
- **分类顺序**：`anime`、`book`、`music`、`game`。
- **Bilibili UID**和可选 TMDB 配置。
- **每页文章数**：建议根据卡片高度和首屏密度调整。

这些页面是否对外开放，仍由页面开关决定。

### 图片优化

| 字段 | 说明 |
| --- | --- |
| 输出格式 | `webp`、`avif` 或 `both` |
| 压缩质量 | `1` 到 `100`，常用范围 `70` 到 `85` |
| 不发送来源域名 | 为匹配域名的图片添加 `no-referrer`，用于处理防盗链 403 |

只有由 Astro 管理的图片才能参与完整优化；图片越多，构建时间越长。

## 个人资料

**入口：后台 → 基础配置 → 个人资料**  
**手动配置对象：`profileConfig`**

| 字段 | 说明 |
| --- | --- |
| 头像 | 可以使用本地资源或网络 URL |
| 名字 | 显示在个人资料组件中 |
| 个人签名 | 一句简短介绍 |
| 个人链接 | 名称、图标、URL 和“显示名称”开关 |

图标使用 Iconify 名称，例如 `fa7-brands:github`。后台新增链接时会自动展开新项目，已有项目默认折叠，方便管理较长列表。

```ts
export const profileConfig = {
  avatar: "assets/images/avatar.avif",
  name: "你的名字",
  bio: "一句话介绍自己。",
  links: [
    {
      name: "GitHub",
      icon: "fa7-brands:github",
      url: "https://github.com/your-name",
      showName: false,
    },
  ],
};
```

## 公告

**入口：后台 → 基础配置 → 公告**  
**手动配置对象：`announcementConfig`**

公告通常由侧边栏中的公告组件显示。可以设置：

- 标题与内容。
- 是否允许读者关闭。
- 是否启用链接。
- 链接文字和 URL。
- 是否作为外部链接打开。

要真正看到公告，还需要在“基础组件 → 侧边栏与组件”中启用 `announcement` 组件。

## 背景壁纸

**入口：后台 → 基础配置 → 背景壁纸**  
**手动配置对象：`backgroundWallpaper`**

背景壁纸字段较多，后台会把图片、横幅文字、打字机、水波纹、渐变和轮播等对象折叠成摘要卡片。

### 壁纸模式

| 模式 | 说明 |
| --- | --- |
| `banner` | 首页和文章顶部显示横幅壁纸 |
| `fullscreen` | 壁纸覆盖整个视口背景 |
| `overlay` | 全屏壁纸与半透明卡片叠加 |
| `none` | 不使用壁纸，仅显示主题背景色 |

### 图片与视频

- 桌面端和移动端可以分别设置一张图片或多张图片。
- 多张图片在未开启轮播时，每次刷新随机选择一张。
- 视频地址可以是一条或多条，多条支持顺序或随机切换。
- 网络图片和公开资源不会经过 Astro 优化，应提前压缩体积。

```ts
src: {
  desktop: ["assets/images/DesktopWallpaper/custom-1.avif"],
  mobile: ["assets/images/MobileWallpaper/custom-1.avif"],
  playerUrl: [],
}
```

### 通用显示

| 设置 | 说明 |
| --- | --- |
| 遮罩暗度 | `0` 到 `1`，数值越大文字越清晰、图片越暗 |
| 视频模式 | `order` 顺序播放，`random` 随机播放 |
| 横幅标题 | 控制标题、副标题和字号 |
| 打字机 | 控制输入、删除和停顿时间 |
| 文章横幅信息 | `description` 显示摘要，`meta` 显示日期、字数和阅读时间 |
| 导航透明模式 | `semi`、`full` 或 `semifull` |
| 毛玻璃 | 可设置开关和模糊度，较高模糊会增加渲染开销 |

### 水波纹、渐变与轮播

- 水波纹可以分别控制桌面端和移动端，移动设备性能较弱时建议关闭。
- 关闭水波纹后，渐变过渡可以让壁纸底部自然融入页面背景。
- 轮播只在配置多张图片时生效。
- 轮播间隔单位为毫秒；过短会影响阅读稳定性。
- 过渡效果支持 `fade`、`zoom`、`slide` 和 `kenburns`。

### 模式专属参数

- `banner.position`：图片裁切位置，常用 `center`、`top`、`bottom`。
- `fullscreen.position`：全屏壁纸的图片位置。
- `overlay.zIndex`：背景层级。
- `overlay.opacity`：壁纸透明度。
- `overlay.blur`：背景模糊度。
- `overlay.cardOpacity`：卡片透明度，越小越透明。

建议一次只调整一个透明度或模糊参数，并同时检查亮色、暗色、桌面和移动端。
